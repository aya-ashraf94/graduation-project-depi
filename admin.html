Nafa3ni Admin Dashboard — full build blueprint organized into 6 sections

Full build blueprint for the Nafa3ni admin system — tap a section to explore.

What the admin is

The admin is a regular Nafa3ni user with role: "admin" in MongoDB. They have a public seller profile like any other user, plus a private control panel only they can access.

Dual identity

Admin is both a marketplace participant (has a profile, can list and sell products under "Sold by Nafa3ni") and a platform controller (can moderate users, listings, and reports).

Two interfaces

A regular-user UI (their public profile at /profile/:id and their own listings) plus an admin panel at /admin — hidden from all non-admin routes.

"Sold by Nafa3ni" label

Products the admin posts with soldByNafa3ni: true get a special badge in the marketplace — exactly like "Sold by Amazon" on Amazon.com.

The 6 capabilities to build

Everything the admin needs, mapped to what already exists vs. what's new.

1. Admin profile page existing page

The existing /profile/me page already works for admin. Extend it with an "Admin control panel" link button visible only when role === 'admin'.

2. Admin product listings existing page

The existing create-listing flow works already. Just set soldByNafa3ni: true when admin posts a listing, and show a special badge on the product card.

3. Dashboard overview new page

Stats: total users, total products, pending reports, orders placed today. Quick-action buttons. Accessible at /admin.

4. User management new page

Table of all users: search, view profile, verify, suspend, delete. Accessible at /admin/users.

5. Listing management new page

Table of all products: view, verify, remove/unpublish any listing. Accessible at /admin/listings.

6. Reports moderation new page

Review all submitted reports. Take action: dismiss, verify listing, or delete. Accessible at /admin/reports. Reports already land in MongoDB — you just need to read them.

Admin's public profile

The admin's profile at /profile/:id is identical to any seller's — it shows their bio, listings, reviews, orders, and wishlist. No changes needed to the existing page except one addition.

Add an "Open admin panel" button

In the existing my-profile component, detect currentUser.role === 'admin' and render a prominent button that routes to /admin. This should be visible only on the admin's own profile, not when other users view it.

Admin badge on public profile

Show a small "Official" or "Nafa3ni Team" badge next to the admin's name on their public profile (similar to the existing isVerified badge logic, but using role === 'admin' as the condition).

No UI change on the edit modal

The admin uses the same profile edit modal as every user (bio, avatar, password, etc.). No extra admin-specific fields needed there — all moderation is done in the separate admin panel.

Selling products as "Sold by Nafa3ni"

The soldByNafa3ni field already exists in the Product MongoDB schema — this is already thought out. You just need to wire it up.

Step 1 — Admin creates listing normally

The admin navigates to /listings/create just like any user and fills the 3-step form. The existing flow doesn't change at all.

Step 2 — Auto-set soldByNafa3ni: true on POST

In the backend productController.js, when creating a product, detect if the authenticated user has role === 'admin' and automatically append soldByNafa3ni: true to the saved document. The frontend doesn't need to send this flag — the backend sets it silently.

Step 3 — Show badge on product cards

In the product card component (used in product-list, home page, search results), check product.soldByNafa3ni and render a distinct "Official Store" badge. The product detail page should also show a trust message — "Shipped and sold by Nafa3ni" — in the seller card area.

Admin panel pages to build

Four new Angular pages, all under the route prefix /admin, all guarded by a new AdminGuard.

/admin — Dashboard overview

Stat cards: total users, total listings, open reports, orders today. A table of the 5 most recent reports with quick action buttons. Navigation links to the other admin sub-pages. Fetches data from existing API endpoints combined into one view.

/admin/users — User management

Paginated table: avatar, name, email, role badge, isVerified badge, total sales, registration date, actions column. Actions: "View profile" (links to /profile/:id), "Toggle verify" (PATCH isVerified), "Delete user" (DELETE). Search bar at the top filters by name or email.

/admin/listings — Listing management

Paginated table: product image thumbnail, title, seller name, category, price, status badge (active/sold/draft), soldByNafa3ni flag, viewCount, posted date, actions. Actions: "View" (links to /products/:id), "Toggle verify" (isVerified), "Remove" (DELETE). Filter by status, category.

/admin/reports — Reports queue

Table of all submitted reports from MongoDB: product title, reporter name, reason, details, submitted date, actions. Actions: "View listing", "Delete listing", "Dismiss report". This hits the existing Reports collection — you only need the backend GET endpoint.

New backend endpoints to add

All require a new adminMiddleware.js that chains after authMiddleware.js and checks req.user.role === 'admin'.

User management endpoints

GET /api/admin/users — all users, paginated. PATCH /api/admin/users/:id — update isVerified or role. DELETE /api/admin/users/:id — delete account.

Listing management endpoints

GET /api/admin/products — all listings, paginated. PATCH /api/admin/products/:id — set isVerified or force-change status. DELETE /api/admin/products/:id — remove any listing (bypass ownership check).

Reports endpoint

GET /api/admin/reports — all reports with full join (populate productId, reporterId). DELETE /api/admin/reports/:id — dismiss a report.

Stats endpoint

GET /api/admin/stats — returns { totalUsers, totalProducts, openReports, ordersToday } in one call for the dashboard overview page.

New backend files

middleware/adminMiddleware.js

Runs after authMiddleware. Checks req.user.role === 'admin' and calls next() or returns 403 Forbidden.

controllers/adminController.js

Handles all admin-specific logic: getUsers, patchUser, deleteUser, getAllProducts, patchProduct, deleteProduct, getReports, deleteReport, getStats.

routes/adminRoutes.js

Registers all admin endpoints under /api/admin, applying both authMiddleware and adminMiddleware to every route.
